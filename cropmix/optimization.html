Optimisation

Search fixed-composition planting designs with count-preserving simulated annealing.

Exact optimiser API#

OptimizationConfig
OptimizationConfig(iterations=500, n_runs_per_candidate=20, final_runs=500, initial_temperature=0.5, cooling_rate=0.99, seed=12345, final_seed_offset=50000000)

Validated settings for swap-based simulated annealing. Iterations may be zero; replication counts and temperature must be positive; cooling rate lies in (0,1].

optimize_mixture
optimize_mixture(field, variety_counts, system, scenario, *, objective="expected_yield", config=None, initial_design=None, transmission_draw=None)

Search arrangements while preserving exact counts. If no initial design is supplied, an exact-count random design is generated using the config seed.

Built-in objectives#

NameInternal score (maximised)
expected_yieldresult.mean_yield
min_final_incidence-result.mean_final_incidence
yield_stabilityresult.mean_yield - result.yield_sd

You may also pass any callable f(SimulationResult) -> float. A custom objective can therefore include economic costs or risk penalties as long as larger values mean better designs.

Common random numbers#

All candidate designs in one optimisation use the same simulation seed block (config.seed + 1,000,000). This induces paired stochastic noise and improves precision of design differences. Evaluated assignments are cached so identical designs are not simulated twice.

Annealing and final evaluation#

Each proposal swaps two heterotypic labels. Improvements are accepted; worse scores may be accepted with probability exp(delta/temperature). The temperature is geometrically cooled. The best design found is then re-simulated with config.final_runs using config.seed + final_seed_offset, with final states retained.

OptimizationResult#

OptimizationResult
OptimizationResult(best_design, best_score, final_result, history, objective_name, variety_counts, evaluations)

Stores the best found design and search trace. history has iteration, current_score, best_score, accepted and temperature columns; evaluations is the number of unique designs actually simulated.

OptimizationResult.summary
result.summary()

Insert objective name, optimization score and evaluation count into the final SimulationResult summary.

Examples#

config = cm.OptimizationConfig(
    iterations=1000,
    n_runs_per_candidate=30,
    final_runs=1000,
    cooling_rate=0.995,
    seed=123,
)
opt = cm.optimize_mixture(
    field,
    {"A":60, "B":40},
    system,
    scenario,
    objective="expected_yield",
    config=config,
)
print(opt.summary())

# User-defined risk-adjusted objective
def risk_adjusted(r):
    return r.mean_yield - 2.0*r.yield_sd
opt2 = cm.optimize_mixture(field, {"A":60,"B":40}, system, scenario, objective=risk_adjusted)
Heuristic result, not proofThe fixed-count design space is combinatorial. best_design means best found under the declared objective, seed, candidate-run count and annealing schedule; it is not a certified global optimum.
