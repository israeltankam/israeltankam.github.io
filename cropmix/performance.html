Performance & HPC

Choose the appropriate computational backend and run large workloads reproducibly.

Core complexity#

The geometry-general simulate_mixture() calls ExponentialKernel.prepare(field), which builds pairwise distances, movement probabilities and a CDF. Memory therefore scales quadratically with the number of sites. The Numba event loop is fast after compilation, but it does not remove dense-kernel memory.

Choose the computational path by geometry#

Problem structureRecommended path
Irregular, surveyed, masked or polygonal fieldGeometry-general simulate_mixture().
Small to moderate regular gridGeometry-general simulator; simplest path and full core API.
Large binary square latticecropmix.publication_backend.prepare_structured_kernel() with run_ensemble().

First-call compilation#

The first simulation in a Python process pays Numba compilation cost. Subsequent calls reuse compiled functions when possible. Time software benchmarking only after a warm-up call if you want steady-state performance.

Adaptive Monte Carlo#

The regular-grid backend accumulates batches from min_runs to max_runs, checks final-incidence MCSE and yield MCSE relative to the mean, and can retain site infection probabilities. This is preferable to picking a nominal run count without precision auditing.

Cluster execution#

For long-running ensembles, use a batch scheduler such as SLURM, write results incrementally, and cache completed scenario/design combinations so interrupted jobs can resume without repeating finished work.

# Generic SLURM pattern from the delivered cluster workflow
sbatch slurm_100x100.sbatch
squeue -u "$USER"
tail -f cropmix_100x100_<jobid>.log
Regular-grid backend is specialisedIts efficiency comes partly from assuming a square binary two-variety lattice. It is not a drop-in replacement for arbitrary geometry or arbitrary numbers of varieties.
