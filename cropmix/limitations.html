Limitations & model boundaries

Know exactly what Cropmix 0.2.0 does not yet claim: PT spatial dynamics, arbitrary-grid publication metrics, globally optimal designs or automatic biological calibration.

Current model boundary: SPT spatial dynamics

PathogenParameters and the EpiPvr bridge can represent PT inference, but simulate_mixture() and solve_mean_field() implement SPT only. A PT system is rejected rather than simulated without a vector latent stage.

Core simulation uses dense movement matrices

Arbitrary finite geometries are supported, but dense O(M²) kernel preparation limits practical field size. The large 100×100 analysis uses a separate structured publication backend specialised to a square binary lattice.

Publication metrics are not yet arbitrary-geometry/multi-variety metrics

The core pairwise_mixing_metrics() works on arbitrary coordinates. The 12-metric manuscript implementation in publication_backend assumes a square binary 0/1 grid. The scientific descriptors can motivate general metrics, but that does not make the current binary code automatically valid for every composition/geometry.

Optimisation is heuristic

Simulated annealing explores a tiny fraction of large combinatorial spaces. Report search settings and final independent re-evaluation; do not claim global optimality.

Biological scale is external evidence

assess_mean_field_consistency() reports where a well-mixed approximation becomes adequate. It does not infer insect dispersal. The CBSD value a=2.625 m is a case-study literature translation, not a package default for other pathosystems.

Vector abundance m is a model scenario quantity

Mapping field whitefly counts to integer vectors_per_plant requires an independent, prespecified interpretation for validation; it should not be tuned against the same epidemic outcomes one is trying to predict.

Yield model is state-based

Each Variety supplies healthy and infected yields. Cropmix does not currently implement a mechanistic crop-growth model, infection-time-dependent yield damage curve, market price dynamics or spatial resource competition unless a user incorporates such quantities in downstream/custom objectives.

No automatic Bayesian outer loop

The core accepts one coherent TransmissionDraw per simulation call. Full nested posterior predictive propagation or Bayesian optimisation is constructed by user/workflow code looping over joint parameter draws.

Experimental validation remains separate

Simulation agreement with another model is not empirical validation. Parameterisation experiments and prospective spatial field outcomes should remain independent of movement-scale and design tuning.
